# FPGA Auto 1.4.2 / Vivado Debug MCP

Vivado 2020.2 的等待命令到达限时后也可能正常返回。此前服务会误把未触发当作采集完成，再上传空缓存。
本版要求 ILA 状态为 FULL 且样本数匹配深度后才接受完成；未触发按 capture_timeout/invalid 结束，停止后确认状态，
随后可换触发条件继续采集。空缓存、部分缓存和未确认的停止均不判通过。

连接采用 GUI 的 `-allow_non_jtag` 参数和显式目标发现，仅对初始目标尚未就绪执行限时重连；
保留精确 target/DNA/part、核 UUID 与位宽核验，不重复执行 VIO/ILA 命令。

用户确认整板掉电并重新上电后，实读 DONE=0；核对历史 BIT/LTX 后，在原 6 MHz 下恢复一次易失配置，DONE/EOS=1、CRC=0。
重新执行单板 VIO 批量/64位回读、五个 ILA 各1024点、条件触发、未触发超时停止、换条件恢复及八页快照，均符合预期。
真实完成通知已由当前聊天收到并回执。完整证据见 原 1.4.2 包的硬件验证记录（未纳入本仓库）。

原构建与通知代码保留；未改 RTL/XDC/IP，未编译工程或写 Flash。双 FPGA 10G 端到端打流未在本轮执行。
1.3.0、1.4.0、1.4.1 发布包及历史失败记录保留。芯片配置恢复属于本次已授权的外部 Tcl 操作，MCP 本身仍不提供下载接口。
