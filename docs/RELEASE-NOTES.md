# FPGA Auto 1.3.0

1.3.0 新增 `bit` / `start bit` 和 `build --bit` / `start build --bit`，
验收通过后生成当前 Job 专属 `.bit` 并记录大小、哈希；监控页面和完成事件同步显示 bit 状态。
从 1.2.2 升级后，原 build 默认行为保持不变，详见 [BITSTREAM.md](BITSTREAM.md)。本次验证记录单独保存在 RELEASE-VALIDATION.json 的 bitstream_extension 字段。

发布日期：2026-09-17。Windows x64 便携包，内置 Python 3.14.7，适用于 Vivado 2020.2 已有 XPR 工程。

## 沿用 1.2.2 的修复

- 修复启用布线后物理优化时的 `Vivado 12-1015`：`launch_runs -to_step` 使用
  `phys_opt_design (Post-Route)`，不再误用 XPR 内部步骤 ID `post_route_phys_opt_design`。
- 同步修复实现终态识别和 Timing/DRC 打开结果时的检查，保留“流程完成但时序未通过”的独立判断。
- 增加显式运行的真实 Vivado 2020.2 回归脚本：创建全新小工程，覆盖布线后物理优化开启/关闭两条路径，
  使用正式工具中的 Tcl 流程执行综合、实现、读取报告及状态断言，不生成 bitstream。

## 沿用 1.2.1 的能力

- 增加自动打开的本地任务监控页面：阶段进度条、运行时间、主/子进程实时日志、搜索筛选、暂停与导出。
- 增加 `monitor --job` 和菜单选项 6，支持重新查看历史任务；`--no-monitor` 可关闭操作命令的自动展示。
- 监控使用包内 Python 独立进程，只监听本机；关闭页面不影响构建，刷新不调用模型。

## 沿用 1.2.0 的能力

- 增加只读 `discover`：支持明确路径、精确工程名和清单别名，排除历史构建/归档副本，保留已有配置。
- 补充常见 Vivado 2020.2 安装路径识别。
- 增加 `start` 和独立 worker：阶段期间由 Python 等待进程、处理超时与取消，Codex 提交后结束当前轮次。
- 默认通过当前桌面的 app-tools 命名管道发送完成事件，直接唤醒原任务，不依赖 daemon 控制 socket。
- 增加 `notify-check`、`notify-retry`、`notify-ack`、`cancel`，区分构建结果、投递状态与模型接收回执。
- 完善完成事件去重、不确定投递处理、任务 UUID 核对和阶段继续执行规则。
- 修正模拟测试批处理的 UTF-8 编码，使工具解压到中文、空格及 `&` 路径后仍可运行验证。

## 1.3.0 功能验证（2026-09-17）

- 75 项自动测试通过，覆盖 bit 的验收门槛、产物校验、单 Job/锁/总超时、取消及完成事件。
- 本机 Vivado 2020.2 的独立计数器工程通过 RTL 仿真、普通布线完整构建、布线后物理优化完整构建和独立 bit 生成。
- 三次生成的真实 bit 文件均为 16,007,031 字节，Timing/DRC 均通过，文件大小及 SHA-256 与结果记录匹配。
- 独立 bit 前后比较了原工程及 run 文件的内容哈希和修改时间，确认全部未改动。
- 两次完整构建均在原模型轮次结束后完成，并各通过一次事件自动唤醒同一任务；等待期间模型轮次为 0。
- 监控页实际核验独立 bit 的 4 阶段和完整构建的 6 阶段，以及 bit 文件位置、大小和哈希。默认自动弹出网页。

这些测试使用独立工程；未重建或烧录用户的生产工程。独立 bit 测试期间用户主动发来了一条消息，
所以该次只计入完成事件送达验证；自动唤醒结论使用另外两次完整构建的记录。
这些功能在此前的 1.2.2 bit 扩展目录完成验证，发布为 1.3.0 时仅调整版本元数据与说明文档；
Python、Tcl、启动器、运行时及测试代码的哈希保持一致。详细结果在
RELEASE-VALIDATION.json（历史便携包文件，未纳入本源码仓库） 的 `bitstream_extension` 字段。

## 原 1.2.2 验证记录（2026-09-16）

1.2.2 已用本机真实 Vivado 2020.2 对独立计数器小工程完成一次综合和两次实现：
布线后物理优化开启时返回 `phys_opt_design (Post-Route) Complete!`，关闭时返回
`route_design Complete!`。两条路径均通过正式 Tcl 流程读取 Timing/DRC 报告，
另外通过 20 项完成状态断言，并确认原步骤名仍能复现 `12-1015`、全程未生成 bitstream。
这些验证没有重新构建 UDP_I17R_OPT，也不代表该用户工程已通过验收。

进度窗口修订后共 59 项自动测试通过，覆盖工程发现、配置保护、独立 worker、取消/超时清理、工程锁、
通知传输及回执，以及新增的 16 项监控测试。浏览器演示使用模拟记录，没有执行真实 FPGA 综合。
Windows 桌面 26.908.9136.0、codex-app-tools 0.1.4 上已完成真实唤醒验收：
原轮次结束后运行 8 秒模拟阶段，Python 发送一次事件，同一任务自动开始下一轮并确认接收，阶段期间新增模型轮次为 0。
任务记录中的消息入口和 event_id 也已核对，用户手动发消息不算自动唤醒。
这次唤醒测试没有执行真实 FPGA 工程综合；验证摘要见 RELEASE-VALIDATION.json（历史便携包文件，未纳入本源码仓库）。

## 使用与升级

1.3.0 沿用 1.2.2 的布线后物理优化修复，并新增可选 bit 生成；旧命令、配置和 Job 记录格式兼容。
已有失败任务的综合结果若仍有效，可在升级后执行 `start impl` 继续实现；不要为恢复实现而直接重跑 `build`，
因为 `build` 会重置并重新执行综合。实现成功后再执行 Timing/DRC 验收。

构建结束后，将 ZIP 内容解压到目标工程根目录，保持 `.agents`、`fpga-auto` 和 `FPGA-START-HERE.md` 同级。
升级会替换同名工具文件；包内不含用户工程 `AGENTS.md`、`fpga.json`、`.fpga`、RTL/XDC/IP 或本机工具链配置。
`tests/bit_regression` 仅包含独立回归用的示例 RTL。
按需保留现有工程配置与运行记录，不能将旧机器的工具链缓存作为另一台机器的安装路径。

桌面通知模式必须从当前 Codex 桌面任务启动并保持应用运行。该本地接口随桌面版本变化，
更换版本或环境后先执行 `notify-check --json`；应用重启导致通道失效时，按事件状态处理重投。
完整规则见 [CODEX-WORKFLOW.md](CODEX-WORKFLOW.md)。
